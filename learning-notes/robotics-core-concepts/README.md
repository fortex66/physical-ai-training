# 로봇 시뮬레이션 핵심 개념 · 실습 03~21

실습에서 배운 개념을 주제별로 다시 찾아볼 수 있도록 정리했다.
각 실습 페이지의 기존 이론 설명은 그대로 유지하며, 아래 링크에서 코드와 실제 결과를 함께 확인할 수 있다.

<a id="physics"></a>
## 1. 물리 설정 — 형상과 물성

3D 모델의 외형만으로 실제 설비의 운동이 결정되지 않는다.
동작 목적에 맞게 강체 설정, 충돌 형상, 질량, 무게중심, 관성, 마찰·반발 특성을 구성한다.
관절이 있는 설비에는 연결 구조·회전축·가동 범위·구동 설정도 필요하다.

- 중력: 강체에 힘을 가해 낙하·처짐을 만든다.
- 충돌 형상: 접촉 여부와 접촉 위치를 계산하는 모양이다. 시각용 상세 메시와 다르게 단순화할 수 있다.
- 질량·관성: 병진·회전 운동이 힘과 토크에 어떻게 반응하는지 결정한다.
- 마찰·반발: 접촉 시 미끄러짐과 튀는 정도에 영향을 준다.

공기 저항을 모델링하지 않은 자유낙하에서는 `a = mg/m = g`이므로 질량이 달라도 낙하 가속도가 같다.
반발 계수는 충돌 전후의 법선 상대 속도와 관련된 값이며, 접촉하는 두 재질의 결합 규칙도 결과에 영향을 준다.

<a id="loop-reset"></a>
## 2. 시뮬레이션 루프와 리셋

Isaac Lab의 기본 흐름은 **명령 전달 → 물리 진행 → 상태 갱신**이다.

```python
scene.write_data_to_sim()
sim.step()
scene.update(sim_dt)
```

고정 시간 간격 `dt`에서 500번의 물리 스텝은 시뮬레이션 시간 `500 × dt`에 해당한다.
이는 PC에서 실제로 기다린 시간과 다를 수 있다.

에피소드 리셋에는 위치·방향과 속도를 함께 복원한다.
로봇은 관절 위치·관절 속도와 필요에 따라 루트 상태·제어 목표도 초기화한다.
`scene.reset()` 같은 버퍼 초기화만으로 임의의 초기 자세로 순간 이동하는 것은 아니다.
상태를 물리 엔진에 쓰는 API와 내부 버퍼를 초기화하는 API를 구분한다.

## 3. Articulation — 관절로 연결된 강체

Articulation은 링크들이 관절로 연결된 로봇·기구를 다루는 구조다.
단일 강체의 위치·속도에 더해 관절 위치·속도·토크와 각 링크의 포즈를 관리한다.

회전 관절 위치는 rad, 직선 관절 위치는 m로 표현한다.
팔 관절과 그리퍼 관절이 같은 배열에 있어도 단위와 역할이 같다고 가정하면 안 된다.
관절 위치 목표와 토크 목표는 다른 명령이며, 실제 응답은 actuator 설정과 물리 조건에 따라 달라진다.

## 4. 다중 환경과 선택 제어

`InteractiveSceneCfg`에 환경의 구성 요소를 선언하고 `num_envs`로 복제 개수를 지정한다.
`{ENV_REGEX_NS}`를 사용하는 자산은 환경별 경로 아래에 배치한다.
`env_spacing`은 환경 원점 사이의 배치 간격이며 로봇 외형 사이의 빈 공간을 의미하지 않는다.

환경 기준 위치에 `scene.env_origins`를 더하면 이 예제들의 월드 위치가 된다.
환경마다 원점이 다르므로 같은 로컬 위치라도 월드 위치는 다를 수 있다.

`env_ids`는 제어할 환경을, `joint_ids`는 제어할 관절을 고른다.
선택한 환경에만 명령을 보낼 때는 명령 텐서의 첫 차원이 선택한 환경 수와 맞아야 한다.
다중 환경 복제 자체가 학습은 아니지만, 병렬 실험·강화학습·일부 환경만 리셋하는 구성의 기반이 된다.

## 5. RGB·Depth와 RayCaster

| 센서 | 읽는 데이터 | 해석할 때 확인할 것 |
|---|---|---|
| RGB 카메라 | 픽셀 색상 | 이미지 채널·해상도 |
| Depth 카메라 | 픽셀별 깊이 · m | 광학 축 기준 깊이인지 카메라 중심에서의 거리인지 |

`distance_to_image_plane`과 `distance_to_camera`를 동일한 값으로 가정하지 않는다.

z 좌표는 표면의 월드 높이이며 센서에서 표면까지의 거리와 구분한다.
여러 광선의 높이를 평균 내면 단의 경계에서 중간값이 생길 수 있다.

물리·렌더링 진행 후 센서 데이터를 갱신해 읽는다.
`InteractiveScene`에 등록한 센서는 씬 갱신을 통해 관리하고, 직접 만든 센서는 해당 객체의 갱신을 수행한다.

## 6. 토크·레버·접촉 힘

토크의 크기는 힘과 회전축에서 힘의 작용선까지의 수직 거리의 곱이다.
이번 수평 레버 예제에서는 같은 토크일 때 짧은 레버가 더 큰 접촉 힘을 전달한다.

균일한 빔의 자체 무게와 끝점의 반력을 고려한 정적 평형식은 다음과 같다.

$$
F=\frac{\tau}{L}+\frac{mg}{2}
$$

중력 항이 더해지므로 총 접촉 힘의 비율을 레버 길이의 역비율과 같다고 볼 수는 없다.
이 식은 수평 빔·끝점 접촉·정적 평형을 가정한다.

`ContactSensor.data.net_forces_w`는 대상 강체에 작용하는 월드 기준 순접촉 힘 벡터다.
모터 토크와 다른 데이터이며, 특정 접촉 상대만 읽으려면 센서의 대상·필터 구성을 고려해야 한다.

## 7. URDF와 USD

URDF는 로봇 구조를 표현하는 XML이다.
`link`는 강체 부품, `joint`는 부품 사이의 연결이며,
시각 형상·충돌 형상·질량·무게중심·관성·관절 축과 범위를 기술한다.

Isaac Sim에서는 URDF를 USD로 변환해 장면·물리 자산으로 사용한다.
USD는 로봇뿐 아니라 장면 구성과 여러 자산을 표현하며 여러 레이어·참조 파일로 나눌 수 있다.
URDF 모델과 제어 프로그램은 역할이 다르다. 입력 명령·센서·실험 루프는 별도로 구성한다.

## 8. 좌표계·포즈·정기구학

포즈는 **위치 + 방향**이다.
정기구학은 로봇의 구조와 관절 상태로 말단 포즈를 구한다.
베이스 포즈까지 고정하면 같은 관절 상태는 같은 말단 포즈를 결정한다.

월드 좌표, 환경 좌표, 로봇 베이스 좌표를 구분한다.
원점을 빼는 계산은 평행이동 차이를 제거하지만, 회전이 다르면 회전까지 포함한 좌표 변환이 필요하다.
말단 링크 프레임과 실제 공구 TCP 사이에도 고정 변환이 있을 수 있다.

Isaac Lab의 `body_pose_w`는 `[x, y, z, qw, qx, qy, qz]`로 포즈를 제공한다.
목표 각도와 실제 관절 상태는 다를 수 있으므로, 현재 말단 결과는 실제 상태와 연결해 해석한다.

## 9. 역기구학·Jacobian·DLS

IK는 목표 말단 포즈에서 관절 구성을 찾는다. Jacobian은 작은 관절 변화와 말단 변화의 관계다.
미분 IK는 현재 상태에서 변화량을 계산하고 갱신된 상태로 반복한다.
DLS는 감쇠 항으로 특이점 근처의 과도한 관절 변화를 완화한다.
IK 계산과 실제 관절을 움직이는 PD 구동은 역할이 다르다.

## 11. 차동 구동·유니사이클 모델

차동 구동은 좌우 바퀴의 속도 차이로 이동 방향을 바꾼다.

## 18. 액션 공간과 actuator

같은 정책 출력도 액션 종류에 따라 힘·위치·속도 명령으로 해석된다.
ActionTerm의 scale·offset은 명령 변환이며 actuator 게인이나 범위 제한을 대신하지 않는다.
목표 위치·속도는 즉시 상태 변경이 아니며 실제 추종은 게인·힘 제한·물리에 달려 있다.
기본 Cartpole의 stiffness=0인 상태에서는 position 모드만 바꿔도 위치 추종이 되지 않는다.

## 19. 태스크 설계와 학습 전 baseline

작업 목표를 관측·행동·보상·종료·초기화로 구체화하고 랜덤 행동으로 환경을 확인한다.
보상 감점과 에피소드 종료는 역할이 다르며, 시간 제한은 성공 판정을 대신하지 않는다.
완료 에피소드 평균에는 진행 중인 기록이 빠지므로 유지 시간·실패 사유·작업 오차도 함께 비교한다.
환경 병렬 수와 전이 수를 늘리는 것만으로 정책 가중치가 학습되지는 않는다.

## 20. PPO 실제 정책 학습

현재 Actor로 경험을 모으고 GAE/return을 계산해 Actor·Critic 가중치를 함께 업데이트한다.
환경 step·에피소드·rollout·epoch·iteration을 구분한다. 병렬 경험을 모으는 횟수와 optimizer 횟수는 같지 않다.
PPO clip은 정책 확률비 목적에 쓰이며 액션 범위나 가중치 변화율 제한이 아니다.
학습 지표와 체크포인트를 보관하고 별도 평가로 실제 작업 유지·실패율을 확인한다.

## 21. 고정 정책 평가와 모델 선택

25번은 평균 행동으로 추론하지만 확률적 추론도 가능하다. no_grad와 탐색 샘플링 제거는 다른 기능이다.
최신 체크포인트를 자동 선택하는 것과 성능이 가장 좋은 모델을 고르는 것은 다르다.
성공률은 시간·실패 조건·실제 에피소드 수를 명시하고 여러 초기 상태에서 평가한다.

## 23. PPO의 학습 단위와 미니배치 선택

rollout은 새 경험 수집 구간, epoch는 그 경험 전체를 학습에 사용하는 횟수, iteration은 수집과 학습을 묶은 반복이다.
26번은 49,152개 전이를 네 미니배치로 나눠 5 epoch 사용하며 미니배치마다 가중치를 바꾼다. episode 완결과 학습 주기는 별개다.
통배치 5회도 가능하다. 미니배치의 메모리·변동성·수정 빈도와 실제 정책 성능을 함께 비교한다.
