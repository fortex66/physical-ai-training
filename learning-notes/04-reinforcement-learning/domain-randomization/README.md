# Domain Randomization과 강화학습

## 1. 하나의 정확한 가상 환경보다 여러 가능한 환경을 경험한다

**Domain Randomization은 학습 중 환경의 물성·센서·초기 상태·외란 등을 정한 범위에서 바꾸는 방법이다.**
예를 들어 실제 로봇의 적재량이 달라질 수 있다면, 학습 때도 질량이 다른 가상 로봇을 경험하게 한다. 정책이 한 질량에서만 잘 작동하는 행동에 의존하지 않도록 만드는 것이다.

‘로봇은 매번 아무 행동이나 해본다’와는 다르다. 랜덤화하는 대상은 **환경 조건**이고, 로봇의 행동은 학습 중인 정책이 낸다.
29번 데모만은 환경 변화를 살펴보기 위해 행동도 무작위로 만든다. 학습된 정책이나 가중치 업데이트는 없다.

## 2. Domain Shift와 어떻게 연결되나

| 용어 | 의미 | 보행 예 |
|---|---|---|
| Domain Shift | 학습과 실행의 조건 분포가 달라지는 현상 | 평지 정책을 계단에서 실행 |
| Domain Randomization | 학습 경험을 만드는 조건을 다양화하는 기법 | 학습 때 여러 질량·마찰·외란·지형 사용 |
| Sim-to-real gap | 시뮬레이션과 현실 사이의 모델·센서·구동 차이 | 실제 모터 지연·마찰·센서 노이즈 |
| Curriculum | 학습 진도에 맞게 난이도 등을 조절 | 쉬운 지형에서 성공하면 더 어려운 지형 |
| Fine-tuning | 기존 가중치에서 새 경험으로 추가 학습 | 평지 정책을 거친 지형에서 추가 업데이트 |

Domain Randomization의 목표는 현실에서 생길 변동을 학습 경험 안에 포함시켜 전이를 돕는 것이다. **현실이 반드시 랜덤화 범위 안에 들어온다는 보장은 없다.**
질량만 다양화했다고 보지 못한 계단 높이·카메라 가림·긴 통신 지연까지 모두 해결하는 것은 아니다.

## 3. 무엇을 랜덤화할 수 있나

| 범주 | 바꾸는 항목 | 바꾸는 이유 |
|---|---|---|
| 물성·동역학 | 질량·관성·마찰·질량 중심 | 적재·부품·접촉 불확실성 |
| 구동·시간 | 모터 강도·감쇠·지연·주기 | 모델과 실제 actuator 차이 |
| 초기 조건·명령 | 자세·관절 속도·목표 속도 | 다양한 상태에서 회복·추종 |
| 교란 | 속도 변화·외력·외부 토크 | 예기치 않은 힘에 대응 |
| 지형 | 높이·경사·턱·배치 | 새로운 접촉 조건에 대비 |
| 센서·시각 | 노이즈·가림·조명·재질 | 실제 측정·영상의 차이 |

29번은 질량·초기 관절 상태·속도 교란·외력 이벤트를 설정한다. 마찰·센서·시각 랜덤화를 모두 구현한 코드는 아니다. 특히 관측 corruption은 꺼져 있다.

## 4. 언제 샘플링하느냐도 설계다

**환경별 한 번 → episode마다 → 실행 중 일정 간격**은 서로 다른 학습 문제를 만든다.

- `startup`: 환경 생성 때 질량을 샘플링하면 병렬 환경마다 서로 다른 물성을 갖는다. 각 환경의 episode가 바뀌어도 그 물성은 유지된다.
- `reset`: episode마다 초기 자세·속도를 바꾼다. 실패 후 다음 episode는 다른 시작 조건을 경험한다.
- `interval`: 진행 중 외란이나 파라미터를 바꾼다. 환경별 타이머인지 공통 타이머인지, reset 때 다시 시작할지 정해야 한다.

질량을 매 물리 step 독립적으로 바꾸면 실제 하드웨어에서 보기 어려운 불연속 변화를 만들 수 있다. 일정 시간 유지할 물성, 빠르게 변할 노이즈, 충격으로 적용할 외란을 구분한다.
Isaac Lab의 EventManager는 **언제 호출할지**를 관리하고, 이벤트 함수가 **무엇을 바꿀지**를 수행한다. PPO는 그 조건에서 모은 경험으로 정책을 학습한다. 이벤트 매니저가 신경망을 직접 업데이트하는 것은 아니다.

29번의 `startup/reset/interval`은 이 데모에서 쓰는 세 가지 모드다. Isaac Lab 전체 이벤트 기능이 이 세 모드만 지원한다는 뜻은 아니다.

## 5. obs → policy → action → step에 어떻게 들어가나

1. 질량·마찰 같은 조건을 정해 물리 환경을 만든다.
2. 초기 상태를 reset하고 obs를 얻는다.
3. 정책이 obs를 보고 action을 낸다.
4. 현재 물성·지형·외란 조건에서 물리 step이 진행된다.
5. 달라진 상태로부터 새 obs·rew·terminated·truncated를 얻는다.
6. 충분한 전이를 모아 PPO로 업데이트하고 반복한다.

외란은 설정된 시점에 추가되며, 정확한 순서는 환경 구현에 따라 확인한다. v2.3.2 ManagerBasedRLEnv는 물리 진행·종료 판정·종료 환경 reset 후 interval을 처리하고 새 관측을 계산한다. 외력 버퍼는 이후 물리 쓰기 단계에서 적용된다.

같은 정책이 여러 질량·초기 상태에서 보상을 높이도록 학습된다. 별도 조건마다 무조건 다른 신경망을 만드는 것이 아니다.
정책은 로봇의 상태 변화에 반응하면서 다양한 조건에 통하는 제어를 익힐 수 있다. 다만 어떤 질량인지 모를 때 항상 최적 행동을 구분할 수 있는 것은 아니다.

## 6. 랜덤화한 질량을 신경망에도 알려줘야 하나

반드시 직접 입력할 필요는 없다. 29번은 관절 위치·속도 4개만 관측하고 질량은 넣지 않는다.
여러 물성에 공통으로 버티는 정책을 학습할 수도 있고, 시간 이력·기억으로 동역학 반응을 추정하게 할 수도 있다.

하지만 같은 현재 obs에서도 숨은 질량·마찰에 따라 적절한 행동이 다르면 **부분 관측 문제**가 생긴다.
조건을 알고 입력하는 정책, 관측 이력·RNN·적응 모듈을 쓰는 정책, 환경별로 필요한 물성을 추정하는 방법을 검토할 수 있다. 이런 기능을 랜덤화만 추가했다고 자동으로 얻는 것은 아니다.
학습 때만 아는 물성을 Critic에 주는 asymmetric Actor-Critic도 별도 설계이며 이번 코드에는 없다. Actor에 준 정보는 배포 때도 얻을 수 있는지 확인한다.

## 7. PPO의 학습 단위는 그대로인가

26번의 예라면 `2048환경 × 24 step = 49,152개 전이 → 4미니배치 × 5 epoch` 구조를 유지하면서 환경 조건을 다양화할 수 있다.
rollout 동안 각 환경은 서로 다른 조건의 경험을 내고, 이 경험들을 함께 사용해 하나의 정책을 업데이트한다.
미니배치마다 질량을 다시 바꾸는 것이 아니다. **환경 조건의 샘플링 시점과 저장된 경험의 학습 시점은 다르다.**

| 동작 | 바뀌는 것 |
|---|---|
| startup/reset/interval 이벤트 | 물성·초기 상태·외란 등 환경 조건 |
| policy의 탐색 샘플링 | 주어진 obs에서 선택하는 action |
| PPO optimizer step | 신경망 가중치 |
| epoch 반복 | 이미 수집한 rollout을 다시 사용 |

보상 함수가 그대로여도 조건이 바뀌어 보상 값은 달라진다. 질량을 바꾼 뒤 보상 하나를 받는 것과 그 보상을 이용해 가중치를 업데이트하는 것은 별개다.
29번의 500 step 랜덤 행동은 이 PPO 학습 구조를 실행하지 않으므로 학습한 모델도 생기지 않는다.

## 8. 범위를 넓히면 무조건 더 좋아지나

아니다. 너무 좁으면 현실을 충분히 포함하지 못하고, 너무 넓으면 실제와 무관하거나 제어 불가능한 상황에 학습 자원을 쓸 수 있다.
모든 조건에서 필요한 행동이 크게 다르면 평균 성능과 특정 조건의 최고 성능 사이에 절충도 생긴다. 랜덤화된 조건에서 보상이 낮아졌다는 이유만으로 학습 실패라고 판단할 수도 없다. 실제 평가 조건의 성능을 비교해야 한다.

측정한 질량·마찰·모터·센서 오차를 바탕으로 범위를 고르고, 물리적으로 가능한 조합을 사용한다.
예를 들어 질량을 늘리면서 관성을 그대로 두는 것과 관성도 함께 맞추는 것은 다른 모델이다. 부품 크기나 질량 중심이 함께 바뀐다면 단순한 질량비 관성 보정만으로 충분하지 않을 수 있다.
파라미터를 독립 샘플링하는 것이 현실의 상관관계를 반영하는지도 살핀다. 적재량·관성·질량 중심은 함께 변할 수 있다.

## 9. 이벤트가 실제 실행됐는지 먼저 확인한다

29번은 episode 최대 5초인데 외력 간격은 5~10초, push는 10~15초다. 기본 타이머는 episode reset 때 다시 시작한다.
v2.3.2의 reset→interval 순서까지 고려하면 현재 설정의 두 외란은 발동하지 않는다. 전체 8.33초를 실행해도 짧은 episode 타이머가 계속 초기화되므로 다르지 않다.

등록된 term 목록·설정 요약은 호출 증거가 아니다. 이벤트별 시뮬레이션 시각·env ID·샘플·호출 횟수와 물리 반응을 기록해야 한다.
속도 변경은 임펄스와 비슷한 효과를 내기 위한 상태 조작이며, 실제 접촉력 과정을 재현한 것은 아니다. 지속 외력은 버퍼가 유지되는 동안 적용되므로 적용 기간·좌표계·reset 해제도 확인한다.

## 10. 강건성이 좋아졌다고 판단하는 방법

표준 조건에서 학습한 정책과 랜덤화 조건에서 학습한 정책을 준비해, 같은 미사용 조건·명령·초기 상태·종료 기준으로 비교한다.

| 평가 범위 | 확인할 것 |
|---|---|
| 기준 환경 | 원래 성능을 얼마나 유지하는가 |
| 학습 랜덤화 범위 안의 새 조건 | 같은 범위의 새 seed에서도 견디는가 |
| 범위 경계·범위 밖 조건 | 어디서부터 성능이 무너지는가 |
| 실제 로봇 | 모델 차이·지연·센서·actuator 제약 속에서 동작하는가 |

각 조건별 정해진 episode 수, 여러 seed의 평균·변동성, 실패 원인·명령 추종·토크 부담 등을 기록한다. 병렬 환경에서 먼저 끝난 episode만 모아 비교하는 편향도 피한다.
학습에 쓴 조건과 최종 평가용 조건을 분리하고, 랜덤화 on/off 및 항목별 ablation으로 무엇이 도움이 됐는지 살핀다.
도메인 랜덤화는 널리 쓰는 방법이지만 실제 검증을 대체하거나 모든 전이 문제의 필수·충분 조건이 되는 것은 아니다.
