# P 제어 기반 Waypoint 내비게이션

**Waypoint는 로봇이 방문할 목표점이며, 피드백 제어는 현재 상태와 목표의 차이로 이동 명령을 보정하는 방식이다.**
17번은 목표점까지의 거리와 방향 오차로 JetBot의 선속도·각속도를 정한다.

## 제어 흐름

```text
현재 위치·방향 + 목표점
         ↓ 거리·방향 오차 계산
P 제어 + 속도 제한 + 감속
         ↓ 선속도 v·회전 각속도 ω
좌우 바퀴 각속도 목표
         ↓ 구동과 물리 계산
갱신된 위치·방향 → 다음 제어 계산
```

P는 Proportional, 즉 비례다. 기본 형태는 `명령 = 게인 × 오차`다.
거리 오차가 크면 더 빠르게 전진하고 방향 오차가 크면 더 빠르게 회전하도록 구성한다.
단, 실제 명령에는 최대 속도 제한을 적용한다.

## 거리와 방향

$$
d=\sqrt{(x_g-x)^2+(y_g-y)^2}
$$

```text
목표 방향 θg = atan2(yg - y, xg - x)
방향 오차 eθ = atan2(sin(θg - θ), cos(θg - θ))
```

각도 오차를 ±π 범위로 정규화해 짧은 회전 방향을 사용한다.
현재 179°, 목표 -179°일 때 오차는 -358°가 아니라 +2°로 해석한다.
위치·방향과 목표의 표현 좌표계도 서로 맞아야 한다.

## 게인·속도 제한·도달 반경

| 설정 | 영향 |
|---|---|
| 선속도 게인 | 목표 거리 변화에 얼마나 크게 반응하는가 |
| 각속도 게인 | 방향 오차에 얼마나 크게 반응하는가 |
| 속도 제한 | 과도한 명령 크기를 제한 |
| 방향에 따른 감속 | 회전 중 전진 속도를 줄임 |
| 도달 반경 | 어느 거리에서 다음 점으로 넘어가는가 |

게인이 크다고 항상 더 안정적이지는 않다. 응답 지연과 물리 조건에 따라 과도한 회전·진동이 생길 수 있다.
도달 반경이 있으면 정확한 좌표에서 정지하지 않아도 다음 점으로 전환할 수 있다.
17번은 최종 방향을 별도 도달 조건으로 요구하지 않는다.

## 주행 제어와 다른 기능의 관계

| 기능 | 질문 |
|---|---|
| 위치·방향 추정 | 지금 어디에 있고 어느 방향인가? |
| 주행 제어 | 현재 목표로 가려면 v·ω를 어떻게 보정할까? |
| 경로 계획 | 어떤 목표점·경로를 거쳐 갈까? |
| 장애물 회피 | 충돌을 피하려면 명령·경로를 어떻게 바꿀까? |

17번은 시뮬레이터의 실제 위치·방향을 읽고, 사람이 정한 목표점을 제어한다.
바퀴 오도메트리나 SLAM을 구현한 예제는 아니다.
또한 목표점 접근 제어는 선분에서의 횡방향 오차를 직접 줄이는 경로 추종과 구분한다.
